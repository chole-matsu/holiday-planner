# 休日手帖

**[アプリを開く](https://chole-matsu.github.io/holiday-planner/)**

カテゴリ一覧のカードを **30分刻みで配置し、下端のドラッグで長さを変更** して、一日の予定を組むWebアプリです。HTML / CSS / JavaScriptのみで動き、GitHub Pagesに公開できます。ビルドや外部ライブラリは不要です。

## 使い方

1. 日付を選びます。
2. 読書・散歩・筋トレ・漫画制作などのカードを、00:00〜23:30の30分枠へドラッグします。最初は30分の予定になります。
3. 予定の下端の「↕」を上下にドラッグすると、30分単位で長さを変えられます。たとえば08:30の予定を10:30まで伸ばすと、2時間のひとつの予定になります。ドラッグ中は終了時刻と長さを表示します。
4. 予定の本体をドラッグすると、長さを保って開始時刻を移動します。同じ長さの予定の開始枠へ移動すると入れ替えます。カテゴリ一覧から同じ長さの予定へ置いた場合は置き換えます。それ以外の重複は拒否します。
5. 長さは最短30分、最長は次の予定の開始または24:00までです。同じカードは何度でも使えます。
6. ×で削除、「元に戻す」で直前の配置・移動・長さ変更・削除を取り消せます。

タッチ操作にも対応。ドラッグしづらい場合は「カードをタップ → 時間枠をタップ」で配置できます。キーボードではTabで移動し、EnterまたはSpaceでカード・時間枠を選択します。「↕」にフォーカスして上キーで30分短縮、下キーで30分延長できます。Escapeで選択・ドラッグをキャンセルします。

「カテゴリをつくる」から独自のカテゴリも追加できます。

## 忘れ物チェックリスト

各カテゴリの「持ち物メモ」から、必要なものを1行に1つ入力して保存します。たとえば読書に「本」「メガネ」、散歩に「飲み物」「帽子」を登録できます。空にして保存すると持ち物を削除できます。

その日の予定に使っているカテゴリの持ち物が、予定表の一番下へチェックボックスとして自動で表示されます。同じ名前のものは1項目にまとめ、必要とするカテゴリも表示します。予定の追加・削除やメモの変更に合わせて一覧も更新します。

準備できたものにチェックを付けると、日付ごとに保存します。別の日のチェックには影響しません。予定から外したものは一覧から隠れますが、同じ日にもう一度必要になったときのチェックは保持します。持ち物メモ自体はカテゴリ共通のため、そのカテゴリを使う他の日にも反映されます。既存の予定データはそのまま引き継ぎます。

## 起動

Node.js 20以降を用意して、このフォルダで実行します。

```sh
npm start
```

http://127.0.0.1:4173 を開きます。`index.html`の直接ダブルクリックではなくHTTPサーバー経由で使ってください。

## 保存

予定とカテゴリは、このサイトを使っているブラウザのlocalStorageに保存します。アカウントやサーバーへの予定の送信はありません。別端末や別ブラウザには同期されません。ブラウザのサイトデータを消すと予定も消えます。GitHub Pagesへ公開したURLとローカルのプレビューの保存領域も別です。

保存領域の読み込みに失敗した場合、元データを上書きしないよう自動保存を停止し、画面に表示します。

従来の1時間刻みの保存データは、開始時刻と1時間の長さを保持して自動で新形式に移行します。持ち物メモやチェックも引き継ぎます。移行後の最初の保存時には、変更前のデータを別キーへバックアップします。

## 通知

「通知をオンにする」を押し、ブラウザで許可すると、今日の予定の開始時刻に通知します。日時は端末のローカル時刻です。HTTPSまたはlocalhostと、通知に対応したブラウザが必要です。

**この版はページを開いて動作している間の通知です。ページを閉じた状態や端末のスリープ中には通知できません。** バックグラウンドでタイマーが制限されると通知が遅延または欠落します。毎時00分・30分の最初の1分以内に15秒間隔で確認し、開始する予定だけを通知します。2時間などの長い予定も途中では再通知しません。通知音や表示はOS・ブラウザ設定に依存します。スマートフォンのブラウザによっては利用できません。複数タブで通知をオンにした場合は重複することがあります。

アプリを閉じた状態の通知には、Web Push配信サーバーと端末登録の追加が必要です。このリポジトリには配信サーバーは含まれません。

## GitHubへの登録と公開

リポジトリ: [chole-matsu/holiday-planner](https://github.com/chole-matsu/holiday-planner)

付属の `.github/workflows/pages.yml` は、`main` ブランチの変更時にテストを行い、`dist` をGitHub Pagesへ配信します。

1. GitHubで対象リポジトリの **Settings → Pages → Source** を **GitHub Actions** に設定します。
2. このフォルダの内容を `main` へpushします。
3. Actionsの「Deploy holiday planner」の成功後、Pagesに表示されたURLを開きます。

公開されるのはアプリのコードと画面です。ブラウザに保存された予定がリポジトリに含まれることはありません。

## 検証

```sh
npm test
```

予定の配置・移動・入れ替え・伸縮、重複防止、24:00の境界、旧データからの移行、持ち物とチェックの保存を20件のテストで検証します。

ブラウザ確認済み: ドラッグによる配置・入れ替え、クリックによる配置、削除・取り消し、再読み込み後の保存維持。390px幅で横方向のはみ出しがないことも確認しました。モバイルの実機タッチ操作・実機通知・開始時刻のOS通知は未検証です。

対応ブラウザではWebMCPの `place_holiday_activity` から同じ配置処理を呼び出せます。`hour: 9.5` は09:30、`durationMinutes: 120` は2時間です。長さを省略した場合は30分になります。重複や日付をまたぐ配置は拒否します。

## 構成

- `dist/`: 公開用のアプリ本体
- `tests/`: データ処理のテスト
- `server.mjs`: 開発用ローカルサーバー
- `.github/workflows/pages.yml`: テストとGitHub Pages配信
